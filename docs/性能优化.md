# ModernChat-mobile 性能优化

本文档记录手机端已经落地的性能策略、验证方式和后续改动必须遵守的约束。目标是在不牺牲高内聚低耦合结构的前提下，减少主线程重建、网络请求和安装包体积。

## 1. 已落地的优化

| 领域 | 问题 | 做法 | 代码位置 |
|---|---|---|---|
| 会话列表刷新 | WS 事件触发 `AsyncLoading`，整页闪烁且重建 | 保持旧数据、后台拉取成功后整体替换；错误时保留旧数据 | `ConversationListController._load` |
| 单条消息 | 每条 `message` 事件都重新请求会话列表 | 能从事件解析出消息时，直接更新对应会话的预览、时间、类型和未读数 | `ConversationListController._applyMessageEvent` |
| 高频事件 | 群成员、用户资料变化短时间连续到达 | 260ms 节流后做静默刷新 | `_scheduleRefresh` |
| 消息去重 | 每次真实消息回包都遍历已加载消息查 ID | 用 `_messageIds` 集合做 O(1) 判断，替换乐观消息时回收临时 ID | `MessageListController` |
| 时间格式化 | 列表项构建时反复 `DateTime.parse` | 有限缓存的时间/日期格式化器；日期分组用 ISO 前 10 位比较 | `core/utils/message_time_formatter.dart` |
| 输入状态 | 每敲一个字符都 `setState` 重建整页 | 输入框发送按钮、搜索清除按钮使用 `ValueListenableBuilder` | `ChatRoomPage`、`ChatListPage`、`ContactsPage` |
| 列表绘制 | 长列表项重复布局和重绘 | `ListView.builder`、`ValueKey`、`RepaintBoundary` | 会话列表、消息列表、联系人列表 |
| Tab 状态 | 切换底部导航重复请求 | `IndexedStack` 保留各 tab 状态 | `AppShell` |
| 安装包 | 单一 APK 包含所有 ABI，体积大 | CI 使用 `--split-per-abi` 生成按架构拆分的 APK | `.github/workflows/ci.yml` |

## 2. 状态刷新约束

后台刷新不能再把 `state` 直接置为 `const AsyncLoading()`。只有首次进入页面、没有旧数据时才允许显示全屏 Loading。

```dart
// 不推荐：后台刷新会让列表闪回 Loading 并整页重建
state = const AsyncLoading();
state = await AsyncValue.guard(loader);

// 推荐：保留旧值，成功后整体替换
final previous = state.value;
final result = await AsyncValue.guard(loader);
final next = result.value;
if (next != null) {
  state = AsyncData(next);
} else if (previous == null) {
  state = result;
}
```

新增 WS 事件时先判断是否能局部更新。只有无法从事件负载确定受影响范围时，才走静默刷新。

## 3. 长列表约束

- 必须使用 `ListView.builder` / `SliverList`，禁止用 `Column` 渲染动态消息列表。
- 每个动态 item 必须提供稳定 `ValueKey`，消息优先用服务端 ID，乐观消息用 `clientMsgId`。
- 消息气泡、会话项、联系人项必须包在 `RepaintBoundary` 中。
- 禁止在 `itemBuilder` 中做重复日期解析、数据库/网络访问或创建大对象。
- 时间显示走 `MessageTimeFormatter.time()`，日期分组走 `MessageTimeFormatter.sameDay()`。

缓存容量上限为 300 条，避免消息量很大时缓存无界增长。

## 4. 输入与搜索约束

聊天输入、会话搜索、好友搜索都使用 `ValueListenableBuilder` 做局部更新。新增输入框时：

- 只有发送按钮是否可用、清除按钮是否显示这类局部 UI 监听 Controller。
- 不要因为文本变化调用父组件 `setState`。
- 好友搜索先在已加载的本地列表过滤，不额外发请求。

## 5. 网络与实时事件约束

- REST 地址与 WS 地址只在 `core/network/network_config.dart` 配置。
- 业务模块不得直接创建 Dio；统一使用 `apiClientProvider`。
- token 通过 `ApiClient` 拦截器注入，业务代码不拼 `Authorization`。
- `message` 事件优先更新内存状态；`conv_change` / `user_change` 走节流静默刷新。
- 消息发送必须带 `clientMsgId`，乐观消息与服务端回包按它配对。

## 6. 构建与包体

本地构建 Android 分架构 APK：

```powershell
flutter build apk --release --split-per-abi
```

产物在 `build/app/outputs/flutter-apk/`：

```text
app-armeabi-v7a-release.apk
app-arm64-v8a-release.apk
app-x86_64-release.apk
```

CI 已采用同样命令，并上传全部拆分 APK。发布时优先使用 `arm64-v8a`，兼容性要求高时再提供 `armeabi-v7a`。

本机工作区路径包含中文字符，AGP 会阻止构建，因此 `android/gradle.properties` 中设置了 `android.overridePathCheck=true`。CI 路径为 ASCII，不受影响。若 Windows 本机出现 Kotlin 增量缓存无法关闭的报错，需要先执行 `flutter clean` 再重新构建。

## 7. 验证命令

```powershell
flutter analyze
flutter test
flutter build apk --release --split-per-abi
```

验证标准：

- `flutter analyze` 无 issue。
- `flutter test` 全部通过。
- 列表滚动无明显掉帧；搜索/输入时只有局部 widget 重建。
- 收到单条消息时，不再触发整表 Loading 和整表请求。
- 聊天日期分组显示正确，时间显示不因缓存变成空字符串。

## 8. 后续改动检查清单

提交前逐项确认：

1. 新增 Provider 是否引入了不必要的整页 `watch`？
2. 后台刷新是否保留了旧数据？
3. WS 事件是否能局部更新而不是整表刷新？
4. 动态列表是否有稳定 Key 和 `RepaintBoundary`？
5. `itemBuilder` 是否避免了日期解析、网络请求和大对象创建？
6. 输入相关 UI 是否用 `ValueListenableBuilder` 局部更新？
7. 新增资源是否声明在 `pubspec.yaml` 的 `assets`？
8. Android 构建是否仍能按 ABI 拆分？
